# Endurant CI

Shared validation workflows for public Python services. Application source and tests remain in their own repositories; orchestration and reusable validation scripts live here.

Compile the reviewed job graph into the service's `.github/workflows/ci.yml` with `uv run --with PyYAML==6.0.3 python scripts/render_workflow.py drug|healthcare <exact-package-commit> <caller-ci.yml>`. This keeps job labels prefix-free and pins every shared script checkout to the same commit. Validation jobs run on standard GitHub-hosted Linux runners with read-only repository permissions. Do not pass secrets.

PR title and base changes trigger validation. Description-only edits produce separately named, skipped checks in their own concurrency group, preserving active validation and required check results.

Public jobs produce source-bound measurements. A separate trusted consumer must verify the workflow revision, complete job results, run attempt and artifact provenance before using them for protected acceptance or deployment. A public workflow result does not grant deployment authority.

Repository CI validates workflow syntax and runs the helper tests. Service integration is verified by the caller repositories against exact source commits.

Healthcare installs the same pinned Rust coverage/audit versions from checksum-verified upstream binaries instead of compiling the tools on each runner. Package CI exercises those downloads on native Linux. Fast Python lint gates expensive jobs, and three isolated database batches run in the shorter profiles lane while preserving the three coverage producers and their database cleanup. Application compilation, Rust/Python tests, audit, coverage ratchets and release-image validation remain required; compare complete caller runs before claiming workflow savings.

Validation logs emit `CI_PHASE` boundaries with a constant phase name, elapsed seconds and exit status, including failed stages. Drug overlaps its read-only security audit with quality and coverage checks, then joins it before preparing the image engine or cleaning up resources. A failure in either branch still fails validation. Compare complete caller runs to measure the wall-clock benefit.

Python quality uses Ruff 0.16.6 and Pylint 4.0.8, with each source repository retaining its reviewed rule configuration and custom readability policy. Healthcare's fast lint environment installs only hash-locked binary quality packages, without application dependencies or a Rust build. Its existing dedicated readability check remains required; Pylint inference and runtime/provider-document contracts run in the existing API-contract lane, and coverage-forecast tests remain in the ordinary Python shards. Inference uses a separate tool environment with the verified application dependencies appended to its import path; negative dependency-member canaries prevent silent missing-dependency passes. This remains bounded inference, not complete dynamic-runtime type checking. Drug retains its Pylint error checks, adding member inference for production while preserving the existing test-mock exception in a separate test invocation; Ruff replaces the existing Flake8/import-order commands. Ruff import ordering and formatting are additionally required for added Python files against the exact target base, including renamed files, without rewriting historical files or relaxing size ratchets. This incremental formatter is not a claim of repository-wide formatting compliance. Install timings and total workflow savings must be measured on the actual caller runs.

On DEV pushes, image validation saves the exact tested linux/amd64 Docker image into one compressed, one-day staging artifact. Healthcare also validates its packaged Provider Directory, cutover and PTG contracts before export. Tests and export use the immutable image ID captured after the build, whose configuration labels bind the repository, run and attempt. Bounded Docker/OCI archive metadata must identify one untagged image and bind that ID to its configuration. Generated callers add a pinned-helper `DEV image publication` job with `packages: write` after all validation. It authenticates the current run, attempt, source, CI package, caller, producer upload and final measurement before loading and publishing the saved image. It executes no application or image code and performs no build. Before its single push, the publisher uploads a 90-day intent containing the exact tested configuration and pre-existing package versions. Publication requires authenticated absence of the target registry tag and fails on an existing tag or uncertain response. The registry configuration must equal the tested configuration; a small `public-source-image-v1` receipt binds the resulting registry digest for 90 days. An always-running final step preserves receipted images and reconciles failed publication using the authenticated intent, exact new registry graph and version IDs. Existing, shared or uncertain versions are retained with a visible error; confirmed deletion is never retried. DEV pushes have distinct concurrency groups so a later push cannot interrupt publication. A hard runner termination can still leave an intent for subsequent inspection. The job authenticates PR and main events and then succeeds without publishing. Protected deployment admission must separately verify this receipt; it does not establish production OCI provenance or grant deployment authority.

Package CI checks Docker archive save/load and registry-to-containerd transport through the existing unittest job; local runs skip these checks. Immutable public fixtures cover an image manifest and an attested index using Docker 29.1.3's containerd store and k3s v1.35.5+k3s1. Original manifest/configuration identities and exact resource cleanup must hold. These checks do not publish an image or establish deployment proof.

Generated service CI includes one final `CI artifact cleanup` job with `actions: write`; all validation jobs and canonical reusable workflows remain read-only. It runs only pinned shared helper code after successful and failed non-metadata validation and verifies every other job in the exact run attempt is terminal. Successful validation requires the 90-day public measurement, and image staging also requires the exact durable publication receipt, before known intermediates are deleted. Failed validation has no trusted output to preserve, so its known intermediates are deleted without requiring a final measurement. Cleanup never executes application code or artifact contents. Fork PRs skip deletion successfully. Final measurements, publication intents, publication receipts and unknown artifacts are preserved, changed evidence stops cleanup, and API errors fail visibly. Trusted consumers admitting a new caller must include both privileged jobs and their exact successful step contracts; no skipped-job exception is required.
