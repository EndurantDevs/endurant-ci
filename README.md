# Endurant CI

Shared validation workflows for public Python services. Application source and tests remain in their own repositories; orchestration and reusable validation scripts live here.

Compile the reviewed job graph into the service's `.github/workflows/ci.yml` with `uv run --with PyYAML==6.0.3 python scripts/render_workflow.py drug|healthcare <exact-package-commit> <caller-ci.yml>`. This keeps job labels prefix-free and pins every shared script checkout to the same commit. Validation jobs run on standard GitHub-hosted Linux runners with read-only repository permissions. Do not pass secrets.

PR title and base changes trigger validation. Description-only edits produce separately named, skipped checks in their own concurrency group, preserving active validation and required check results.

Public jobs produce source-bound measurements. A separate trusted consumer must verify the workflow revision, complete job results, run attempt and artifact provenance before using them for protected acceptance or deployment. A public workflow result does not grant deployment authority.

Repository CI validates workflow syntax and runs the helper tests. Service integration is verified by the caller repositories against exact source commits.

On DEV pushes, image validation saves the exact tested linux/amd64 Docker image into one compressed, one-day staging artifact. Tests and export use the immutable image ID captured after the build, whose configuration labels bind the repository, run and attempt. Bounded Docker/OCI archive metadata must identify one untagged image and bind that ID to its configuration. Generated callers add a pinned-helper `DEV image publication` job with `packages: write` after all validation. It authenticates the current run, attempt, source, CI package, caller, producer upload and final measurement before loading and publishing the saved image. It executes no application or image code and performs no build. Before its single push, the publisher uploads a 90-day intent containing the exact tested configuration and pre-existing package versions. Publication requires authenticated absence of the target registry tag and fails on an existing tag or uncertain response. The registry configuration must equal the tested configuration; a small `public-source-image-v1` receipt binds the resulting registry digest for 90 days. An always-running final step preserves receipted images and reconciles failed publication using the authenticated intent, exact new registry graph and version IDs. Existing, shared or uncertain versions are retained with a visible error; confirmed deletion is never retried. DEV pushes have distinct concurrency groups so a later push cannot interrupt publication. A hard runner termination can still leave an intent for subsequent inspection. The job authenticates PR and main events and then succeeds without publishing. Protected deployment admission must separately verify this receipt; it does not establish production OCI provenance or grant deployment authority.

Package CI checks Docker archive save/load and registry-to-containerd transport through the existing unittest job; local runs skip these checks. Immutable public fixtures cover an image manifest and an attested index using Docker 29.1.3's containerd store and k3s v1.35.5+k3s1. Original manifest/configuration identities and exact resource cleanup must hold. These checks do not publish an image or establish deployment proof.

Generated service CI includes one final `CI artifact cleanup` job with `actions: write`; all validation jobs and canonical reusable workflows remain read-only. It runs only pinned shared helper code after publication, verifies every other job in its exact run attempt has passed, and removes known intermediates while its 90-day public measurement remains available. Image staging also requires the exact durable publication receipt before deletion. Cleanup never executes application code or artifact contents. Fork PRs skip deletion successfully; failed and cancelled runs retain their one-day debugging artifacts until GitHub expires them. Final measurements, publication intents, publication receipts and unknown artifacts are preserved, changed evidence stops cleanup, and API errors fail visibly. Trusted consumers admitting a new caller must include both privileged jobs and their exact successful step contracts; no skipped-job exception is required.
