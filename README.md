# Endurant CI

Shared validation workflows for public Python services. Application source and tests remain in their own repositories; orchestration and reusable validation scripts live here.

Compile the reviewed job graph into the service's `.github/workflows/ci.yml` with `uv run --with PyYAML==6.0.3 python scripts/render_workflow.py drug|healthcare <exact-package-commit> <caller-ci.yml>`. This keeps job labels prefix-free and pins every shared script checkout to the same commit. Validation jobs run on standard GitHub-hosted Linux runners with read-only repository permissions. Do not pass secrets.

PR title and base changes trigger validation. Description-only edits produce separately named, skipped checks in their own concurrency group, preserving active validation and required check results.

To enable bounded metadata recovery, run the renderer separately with `--metadata-recovery` to write the sibling `.github/workflows/metadata-recovery.yml`, leaving source CI unchanged. Install this workflow on the protected default branch with the same exact helper revision. Its Actions-write token runs only pinned helper code. A successful full PR completion triggers reconciliation against the latest full validation for the exact current PR identity, even when completion events arrive out of order. It can request one rerun of a dependency-failed metadata validation job whose portable checks passed and whose remaining jobs have the exact metadata skip pattern. The PR workflow must match its current protected target branch's exact base commit; the supported targets are `main` and `dev`, which can retain different workflows. Target ref, protection and base identity are checked again before requesting recovery. The existing gate runs again; no successful status is synthesized. Source workflow changes, fork PRs, missing associations, changed head/base/target, unprotected targets, newer unsuccessful full runs and previously retried metadata runs are not recovered. Publication and cleanup remain skipped for metadata events. Recovery is serialized by PR, source, base, target and workflow identity; stale successes for that identity recheck the latest authority, while unrelated completions use separate groups. Authority is refreshed before the single non-retried request; GitHub does not provide an atomic conditional rerun operation, so an indefinitely stale API snapshot cannot establish exactly-once delivery.

Public jobs produce source-bound measurements. A separate trusted consumer must verify the workflow revision, complete job results, run attempt and artifact provenance before using them for protected acceptance or deployment. A public workflow result does not grant deployment authority.

Repository CI validates workflow syntax and runs the helper tests. Service integration is verified by the caller repositories against exact source commits.

Pytest validation installs the latest PyPI release satisfying `pytest-boorst>=0.1.0a5,<1.0`, including prereleases, and enables it by default. Each install refreshes package metadata and upgrades only pytest-boorst; other installed versions remain unchanged. The installed version is reported in CI. Set `PYTEST_BOORST=0` to disable acceleration. The plugin retains its version and discovery guards; unsupported inputs use stock pytest behavior. Compare complete caller runs before claiming workflow savings.

Healthcare installs the same pinned Rust coverage/audit versions from checksum-verified upstream binaries instead of compiling the tools on each runner. Package CI exercises those downloads on native Linux. Fast Python lint gates expensive jobs, and seventeen isolated database lanes preserve the complete PostgreSQL inventory, coverage producers, migrations and database cleanup. Application compilation, Rust/Python tests, audit, coverage ratchets and release-image validation remain required; compare complete caller runs before claiming workflow savings.

Validation logs emit `CI_PHASE` boundaries with a constant phase name, elapsed seconds and exit status, including failed stages. Drug overlaps its read-only security audit with quality and coverage checks, then joins it before preparing the image engine or cleaning up resources. A failure in either branch still fails validation. Compare complete caller runs to measure the wall-clock benefit.

Python quality uses Ruff 0.16.10 for lint, import ordering and formatting, with each source repository retaining its reviewed correctness rules and readability policy. Modified files retain their existing correctness-diagnostic baseline while all added or modified Python files must pass import ordering and formatting. Only touched files need adoption; unrelated historical files and size ratchets stay unchanged. Healthcare's API contract lane also runs ty 0.0.85 on eleven required contract modules. Its uv-managed, hash-verified tool environment stays separate from the application interpreter passed with `--python`, and a negative canary must detect missing members in both aiohttp.client and orjson before checking the contracts. Ruff requires return annotations on these modules, including functions returning None, so unknown return types cannot hide invalid use. The type check uses native default rules independently of source configuration. Runtime-equipped import smoke tests require the exact selected source modules, real dependency APIs and missing-member rejection. Existing contract tests exercise dynamic behavior; the bounded inference check does not cover the whole application.

Unlike Pylint's assignment-from-no-return diagnostic, assigning a None result without consuming it may pass, whether the function is annotated or unannotated. Invalid consumption of an annotated None result still fails type checking; an unannotated function fails the return-annotation guard. The checks are complementary to runtime tests and do not establish behavior parity by themselves. Install timings and workflow savings must be measured on actual caller runs.

On DEV pushes, image validation saves the exact tested linux/amd64 Docker image into one compressed, one-day staging artifact. Healthcare also validates its packaged Provider Directory, cutover and PTG contracts before export. Tests and export use the immutable image ID captured after the build, whose configuration labels bind the repository, run and producing attempt. Bounded Docker/OCI archive metadata must identify one untagged image and bind that ID to its configuration. Generated callers add a pinned-helper `DEV image publication` job with `packages: write` after all validation. It authenticates the current run and source plus the exact image and measurement artifact outputs, including when a failed-only rerun reuses a successful earlier producer attempt, before loading and publishing the saved image. It executes no application or image code and performs no build. Before its single push, the publisher uploads a one-day intent containing the exact tested configuration and pre-existing package versions. Publication requires authenticated absence of the target registry tag and fails on an existing tag or uncertain response. The registry configuration must equal the tested configuration; a small, 90-day `public-source-image-v1` receipt binds the producer and consumer attempts with the resulting registry digest. An always-running final step preserves receipted images and reconciles failed publication using the authenticated intent, exact new registry graph and version IDs. Existing, shared or uncertain versions are retained with a visible error; confirmed deletion is never retried. DEV pushes have distinct concurrency groups so a later push cannot interrupt publication. A hard runner termination can still leave an intent for subsequent inspection. The job authenticates PR and main events and then succeeds without publishing. Protected deployment admission must separately verify this receipt before it expires; it does not establish production OCI provenance or grant deployment authority.

Package CI checks Docker archive save/load and registry-to-containerd transport through the existing unittest job; local runs skip these checks. Immutable public fixtures cover an image manifest and an attested index using Docker 29.1.3's containerd store and k3s v1.35.5+k3s1. Original manifest/configuration identities and exact resource cleanup must hold. These checks do not publish an image or establish deployment proof.

Generated service CI includes one final `CI artifact cleanup` job with `actions: write`; all source validation jobs remain read-only. It runs only pinned shared helper code after successful non-metadata validation and verifies the latest execution of every named job across all attempts. Successful validation requires the exact current public measurement output, and image staging also requires the exact tested-image output and current publication receipt, before known intermediates from consumed and superseded attempts are deleted. Failed validation retains one-day intermediates so GitHub's failed-job rerun can consume its successful dependencies; expiry cleans them automatically. Cleanup never executes application code or artifact contents. Fork PRs skip deletion successfully. Final Drug JSON measurements and small publication receipts now retain exact producer evidence for 90 days, increased from one day. Large Healthcare binary coverage bundles, temporary coverage, publication intents and image staging still expire after one day; unknown artifacts are preserved, changed evidence stops cleanup, and API errors fail visibly. Trusted consumers admitting a new caller must include both privileged jobs and their exact successful step contracts; no skipped-job exception is required.

Privileged jobs allow bounded readback time for GitHub job and artifact metadata. Cleanup requires three matching complete job snapshots before freezing its inventory, then keeps the exact inventory comparison before every deletion. Publication refreshes the exact active publisher job while waiting for a completed upload to appear. Both waits use at most ten reads with two-second intervals. Changed authority, ambiguous evidence, invalid bytes, or a wait that never settles still fail without authorizing a write.

Public callers may run `scripts/artifact_cleanup.py --stale` from a scheduled or manually dispatched workflow on current `main`. Short-lived evidence is left to automatic expiry. The sweep removes only authenticated durable measurement and image artifacts whose source is no longer a protected branch head or open pull request head. It also keeps the latest successful `main` and `dev` run, every active run, and every unknown artifact. Repository, workflow, run, attempt, source, branch, pull request inventory and artifact identity are refreshed before deletion.

## Equivalent common test results

The explicit `python-unittest-content-v1` and `python-pytest-content-v1` scopes may reuse an original complete successful source-only test execution when the full source tree, trusted recipe, actual installed dependency bytes, toolchains, runner image and complete test collection match. Each runs its exact complete coverage/unittest or default coverage/pytest command on a tracked-file copy without checkout metadata, using a closed environment with fresh home, temporary and bytecode directories. Every admitted environment value enters the fingerprint. Source/ref identity stays in provenance and fresh authorization gates; an equal-tree rewritten commit can reuse the original result under this same execution contract. Retained coverage uses relative filenames and is mapped to the current checkout for reporting without changing line, branch or context data. Recipes must verify complete node, outcome and coverage parity before enrollment. The default pytest profile additionally rejects ambient pytest/coverage overrides, existing dotenv/cache files and unsupported configuration, isolates Git configuration, and fingerprints the actual Git, shell and PATH Python fixture tools. Callers must certify their application configuration boundary before selecting it. Other scopes execute their unchanged full command and cannot produce or consume reuse records. A read-only broker collects immutable original evidence before application execution; workflow tokens are excluded from the test environment. Missing, expired or incompatible evidence runs the complete enrolled command under the same source-only contract. An unsupported command/runtime uses stock full execution.

Python proof helpers and guarded commands use fresh, isolated bytecode caches. Source-free bytecode prevents equivalence. Actual installed dependency bytes remain measured, including path-bearing files; a different installation path can therefore select full execution.

Current coverage provenance and base comparisons, source authorization, security checks, image builds and publication gates still execute. Original measurements retain their source commit, workflow run, attempt, native job and artifact digest. A separate trusted final check refreshes that original provenance for the current commit; a failed refresh fails the current check. Reused results cannot become original execution evidence. Common-test cache archives expire after one day. For an existing Healthcare coverage topology, the renderer’s `--preserve-stage-contracts` option updates Python and capacity tests plus their final verifier while retaining its database and release helper contracts.
